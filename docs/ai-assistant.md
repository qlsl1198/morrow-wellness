# AI 어시스턴트와 개인화

## 역할

Morrow의 AI는 체크인, 동의받은 건강 요약, 추천 실행 결과와 사용자가 직접 관리하는 메모리를 바탕으로 지금 가능한 짧은 회복 행동과 대화를 만듭니다. 범용 모델을 사용자 데이터로 파인튜닝하지 않고, 계정별로 설명 가능한 컨텍스트를 매 요청에 구성합니다.

## 사용하는 맥락

- 최근 7일 체크인: 상태, 원인, 메모, 시각과 입력 기기
- 최근 타임라인: 건강 신호, 체크인, 사용자 확인 여부
- 추천과 회복 실행 결과: 완료 여부, 체감 효과, 피드백
- 활성 개인화 메모리: 반복 원인, 효과가 있었던/없었던 행동, 선호와 목표
- 최근 대화 맥락: 현재 질문에 필요한 범위
- 사용자가 별도 동의한 경우에만 수면·운동·HRV 등 파생 건강 요약

저장된 과거 답변은 대화 맥락을 만드는 근거일 뿐, 새 질문에 대한 응답으로 다시 반환하지 않습니다. 웹을 새로고침하면 화면의 대화는 새 세션처럼 시작하지만 서버의 계정별 요약과 개인화 메모리는 유지됩니다.

## 추천 생성

1. 상태·원인·시간대와 최근 건강 신호로 안전한 후보 행동을 만듭니다.
2. 과거에 도움이 됐던 행동은 올리고, 불편하거나 효과가 없었던 행동은 내립니다.
3. 짧은 추천 모델이 행동 종류와 실행 시간을 구조화해 선택합니다.
4. 형식·시간·안전 기준을 통과하지 못하면 규칙 기반 개인화 후보로 대체합니다.

행동 종류는 `BREATH`, `WALK`, `WATER_WALK`, `STRETCH`, `FOCUS`, `SCREEN_BREAK`이며, Watch·iPhone·웹의 `지금 바로 실행`은 선택된 종류와 시간에 맞는 실행 화면을 엽니다.

## 모델 라우팅

| 역할 | 기본 모델 | 용도 |
| --- | --- | --- |
| 긴 대화 | `gpt-5.6-sol` | 사용자 질문, 맥락 설명, 안전한 코칭 |
| 짧은 생성 | `gpt-5.6-terra` | Next Best Action, 선제 인사이트, Watch 알림 문구 |
| 장애 대체 | `gpt-5.6-luna` | 재시도 가능한 429·타임아웃·5xx 대체 |

모든 요청은 OpenAI Responses API를 사용하고 원격 저장을 끄며, 계정 ID 원문 대신 안정적으로 해시한 안전 식별자를 전달합니다. 모델 이름과 키는 GitHub Actions secrets와 운영 환경 변수로 주입하고 문서나 코드에 실제 키를 저장하지 않습니다.

```dotenv
OPENAI_API_KEY=sk-your-api-key-here
OPENAI_CHAT_MODEL=gpt-5.6-sol
OPENAI_SHORT_MODEL=gpt-5.6-terra
OPENAI_FALLBACK_MODEL=gpt-5.6-luna
OPENAI_ENABLED=true
MORROW_AI_INCLUDE_HEALTH_DATA=false
```

## 장애 대응

- 429, 타임아웃, 일시적 5xx는 제한된 횟수로 재시도하고 대체 모델을 사용합니다.
- 실시간 AI가 끝내 응답하지 않으면 안전 필터와 계정별 규칙을 적용한 fallback을 새로 생성합니다.
- fallback이나 과거 저장 답변을 다시 모델 입력에 섞어 오류 문구가 장기 기억으로 굳지 않게 합니다.
- `/assistant/status`에서 준비 상태, 역할별 모델, 성공·실패·재시도 수와 최근 실패 유형을 확인할 수 있습니다. 키 값은 노출하지 않습니다.

## 안전 정책

위기 또는 자해 가능성이 있는 표현은 일반 웰니스 추천보다 119·112·자살예방상담전화 109 등 즉시 도움 안내를 우선합니다. 진단, 처방, 약물 변경, 치료 중단 요청에는 의료 전문가 상담을 안내합니다. 생체 신호만으로 정신·신체 상태를 확정하지 않습니다.

## 데이터 흐름

```text
사용자 메시지 또는 추천 트리거
  → 인증된 계정 범위 확인
  → 위기·의료 안전 필터
  → 최근 기록 + 활성 메모리 + 선택적 건강 요약
  → 역할별 OpenAI 모델 호출
  → 형식·안전 검증
  → 대화/추천 저장 및 기기 동기화
  → 실행 결과를 개인화 메모리에 반영
```

## 사용자 제어

- `/personalization/memories`에서 AI가 사용하는 메모리를 확인·생성·수정·삭제할 수 있습니다.
- `/privacy/ai-health-consent`에서 건강 요약의 AI 사용 동의를 바꿀 수 있습니다.
- `/assistant/messages` 삭제는 대화 기록을 지우고, `/users/me/data`는 웰니스 데이터 전체를 삭제합니다.
- 데이터 삭제와 모델 장애 여부는 숨기지 않고 사용자에게 상태로 표시합니다.
